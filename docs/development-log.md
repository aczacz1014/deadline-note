# 개발 및 문제 해결 기록

## 목적과 요구사항

과제 2 안내문에 따라 입력·저장·조회·수정·삭제가 가능한 웹 앱, 실제 웹 배포, GitHub 소스 저장소, 개발 보고서를 준비한다. AI는 대학생이 과제와 팀 프로젝트의 마감·상태를 관리하는 개인용 앱을 기본안으로 제안했다. 사용자는 초기 메시지에서 특정 주제나 기능을 지정하지 않았다.

## 강의와 연결

- Week5 웹페이지와 웹사이트의 기본 구조 및 작동 원리: HTML, CSS, JavaScript의 역할을 나눈다.
- Week5 및 Week6 To-do 실습: 입력 → 목록 표시 → 상태 변경 → 저장의 흐름을 확장한다.
- Week7 webapp_database: 한 기기의 개인용 앱에는 localStorage를 사용할 수 있다는 설명을 적용한다. 서버와 데이터베이스의 역할을 구분하고, 기기 간 동기화가 없는 한계를 밝힌다.
- Week6 웹 배포 및 Week7 Web-database 실습: 소스 저장소, 배포된 웹 앱, 저장 데이터의 위치를 구분한다. 과제는 Vercel·Neon 사용을 필수로 한정하지 않는다.

## 실제 문제 1 백업의 기록 날짜 검증 누락

- 발견: 자동 테스트에서 `createdAt: 1`인 잘못된 백업에 대해 오류가 발생하지 않아 `Missing expected exception`으로 실패했다. 최초 결과는 8개 중 7개 통과였다.
- 원인: `Date.parse()` 결과가 유한한지만 검사하여 숫자 입력도 날짜로 허용했다. 이후 문자열 정렬 시 `localeCompare`를 사용할 수 없는 값이 유입될 수 있었다.
- AI 활용: AI가 데이터 검증 코드를 검토하고 비문자열 타임스탬프를 포함한 백업 테스트를 작성했다. 실패 결과를 바탕으로 수정했다. 사용자가 별도로 보낸 수정 프롬프트는 없다.
- 수정: 문자열 여부와 표준 ISO 타임스탬프 형식을 함께 확인하도록 변경했다. 백업 전체를 검증한 뒤에만 기존 저장 데이터를 교체한다.
- 결과: 해당 테스트를 포함한 8개 테스트가 통과했다. 이후 ID 생성 호환성 테스트를 추가하여 최종 자동 테스트는 9개가 되었다.

## 실제 문제 2 실행 환경에서 과제 등록 실패

- 발견: HTTP 미리보기에서 `예시 과제로 둘러보기`를 누르자 목록은 0개로 남고 `저장하지 못했습니다. crypto.randomUUID is not a function`이 표시됐다.
- 원인: 실행 환경에 `crypto.randomUUID()`가 제공된다고 가정하고 직접 호출했다.
- AI 활용: AI가 실제 브라우저에서 버튼을 눌러 오류 메시지와 화면을 확인한 후 ID 생성 함수를 수정했다. 사용자가 해당 오류를 직접 발견했다고 기록하지 않는다.
- 수정: `randomUUID()` 지원 여부를 먼저 확인하고, 미지원 시 `getRandomValues()`를 사용하도록 했다. 두 기능이 모두 없을 때는 시각과 임의 문자열을 조합한 과제 ID를 생성한다. 이 ID는 인증 토큰이 아니다.
- 결과: 같은 HTTP 미리보기에서 예시 과제 5개 추가에 성공했다. 수동 입력 UI를 통한 신규 과제 등록, 제목 수정, 상태 변경, 완료, 새로고침 후 유지와 삭제도 확인했다.

## 개선 3 모바일 사용 안내 접근 경로

- 발견: 반응형 CSS에서 작은 화면의 사이드바 하단을 숨기므로 그 안에만 있는 사용 안내 버튼도 사라지는 구조였다. 코드 검토에서 확인한 개선 사항이다.
- 수정: 화면 하단에 별도의 사용 안내 버튼을 추가하고 같은 도움말 창에 연결했다.
- 결과: 사이드바가 숨겨져도 문서 하단에서 저장 방식과 백업 주의사항을 확인할 수 있는 구조가 되었다. 모바일 실기기 검증과 구분하여 기록한다.

## 검증 주체와 범위

자동 테스트와 아래 브라우저 조작은 AI 에이전트가 수행했다. 사용자 본인의 직접 사용 소감이나 문제 발견 경험은 아직 이 기록에 포함하지 않는다.

| 항목 | 확인 방법 | 결과 |
| --- | --- | --- |
| 등록 | 가상 과제명, 수업명, 마감, 우선순위, 메모 입력 | 5개에서 6개로 증가 |
| 수정 | 가상 과제 제목과 진행 상태 변경 | 제목과 상태 반영 |
| 완료 및 저장 유지 | 완료 처리 후 새로고침 | 6개 중 완료 2개, 완료율 33% 유지 |
| 검색 | 검증이라는 단어 검색 | 해당 가상 과제 1개 표시 |
| 복합 필터 | 검색 결과에 다른 분류 적용 | 0개 안내와 필터 초기화 표시 |
| 삭제 | 확인 창에서 삭제 선택 | 6개에서 5개로 감소 |
| 백업 저장 | 실제 다운로드 이벤트 확인 | JSON 파일 생성 |
| 데이터 처리 | Node.js 테스트 실행 | 9개 통과 |

## 남은 한계

- 서버 저장과 자동 기기 간 동기화를 제공하지 않는다.
- 공동 편집, 사용자 로그인, 푸시 알림을 제공하지 않는다.
- 저장 공간이 부족하면 저장 실패를 알리고 입력 창을 유지한다. 브라우저 저장 자체가 차단된 환경에서는 정상 저장이 불가능하다.
- 백업 복원과 실제 배포 결과는 확인되는 대로 이 문서와 제출 보고서에 반영한다.
